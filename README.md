# levorules.com

Исходники сайта и открытого курса «Сервиторы».

## Сборка сайта

```bash
npm ci
npm run build
```

Команда создаёт `public/` — единственный каталог, который разрешено публиковать в Cloudflare. Корень репозитория содержит исходники и служебные файлы и не должен раздаваться как static assets.

## Обновление курса

Канонический текст находится в `content/servitors-course.md`.

```bash
npm run content:jsx
```

Команда обновляет полную структуру курса в `site/_servitors-content-1.jsx` и `site/_servitors-content-2.jsx`, каталог `site/_servitors-catalog.jsx`, отдельные модули и поисковый индекс в `dist/course/`. Все эти файлы генерируются из Markdown и сохраняются в репозитории. Вступления, практика и чек-листы сохраняются полностью; дата редакции берётся из Markdown.

`npm run build` создаёт обычные HTML-страницы: `/servitors/`, `/servitors/0/`–`/servitors/10/`, `/guides/`, `/guides/defense-basics/` и `/who/`. Каждая содержит читаемый текст и собственные SEO-метаданные до запуска JavaScript. Старые адреса с `#servitors` и `#servitors-reader/N` продолжают работать. Ссылка на параграф выглядит так: `/servitors/4/#s-4.5`.

React раздаётся с того же домена из `public/vendor/`. Пакет интерфейса курса загружается при открытии курса; JSON конкретного модуля — при переходе к нему, общий поиск — при вводе запроса. Изменение `main` запускает настроенную публикацию Cloudflare. После публикации нужно проверить живые HTML, JS и PDF, а не только успешную локальную сборку.

## Пересборка PDF

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-pdf.txt
python -m playwright install chromium
npm run content:pdf
```

PDF создаются непосредственно в `uploads/` и `uploads/appendices/`. Генератор включает структуру тегов и PDF-outline для доступности.

## Полная проверка

```bash
npm test
```

Проверка заново генерирует данные из канонического Markdown, собирает production-артефакт `public/` и запускает регрессионный аудит структуры курса, опасных формулировок и публичного allowlist. Дополнительно `tools/verify_site.py` сверяет каждую содержательную строку и ячейку модулей с JSON и опубликованным HTML, проверяет общее вступление, канонические адреса, локальные ресурсы и ссылки на разделы. PDF пересобираются отдельно после изменения текста.

## Аналитика курса

`analytics.js` отправляет в GA4 отдельные события воронки курса:

- `course_cta_click` — переход в курс из hero, программы или финального экрана;
- `course_start` — первый запуск курса в текущем браузере;
- `course_resume` / `course_revisit` — возврат к незавершённому / завершённому курсу;
- `course_module_view` — открытие модуля;
- `course_progress` — достижение 25%, 50%, 75% и 100%;
- `course_complete` — явное завершение курса;
- `course_reset` — сброс сохранённого прогресса.

Прогресс хранится локально в `lr_servitor_progress_v1`. Процент считается по числу открытых модулей; 100% фиксируется только после подтверждения завершения в модуле 10.
