# levorules.com

Исходники сайта и открытого курса «Сервиторы».

## Сборка сайта

```bash
npm ci
npm run build
```

Команда создаёт `public/` — единственный каталог, который разрешено публиковать в Cloudflare. Корень репозитория содержит исходники и служебные файлы и не должен раздаваться как static assets.

## Обновление курса

Канонический текст находится в `content/servitors-course.md`.

```bash
npm run content:jsx
```

Команда обновляет полную структуру курса в `site/_servitors-content-1.jsx` и `site/_servitors-content-2.jsx`, каталог `site/_servitors-catalog.jsx`, отдельные модули и поисковый индекс в `dist/course/`. Все эти файлы генерируются из Markdown и сохраняются в репозитории. Вступления, практика и чек-листы сохраняются полностью; дата редакции берётся из Markdown.

Схемы лежат в `content/figures/`: `<id>.svg` и подпись с альтернативным текстом в `figures.json`. Чтобы поставить схему в текст, добавь в Markdown отдельную строку `::fig <id>` с пустыми строками вокруг. SVG встраивается в страницу модуля целиком и рисуется шрифтами сайта; в PDF схемы не попадают, там остаётся полный текст.

`npm run build` создаёт обычные HTML-страницы: `/servitors/`, `/servitors/0/`–`/servitors/10/`, `/guides/`, `/guides/defense-basics/` и `/who/`. Каждая содержит читаемый текст и собственные SEO-метаданные до запуска JavaScript. Старые адреса с `#servitors` и `#servitors-reader/N` продолжают работать. Ссылка на параграф выглядит так: `/servitors/4/#s-4.5`.

React раздаётся с того же домена из `public/vendor/`. Пакет интерфейса курса загружается при открытии курса; JSON конкретного модуля — при переходе к нему, общий поиск — при вводе запроса. Изменение `main` запускает настроенную публикацию Cloudflare. После публикации нужно проверить живые HTML, JS и PDF, а не только успешную локальную сборку.

## Пересборка PDF

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-pdf.txt
python -m playwright install chromium
npm run content:pdf
```

PDF создаются непосредственно в `uploads/` и `uploads/appendices/`. Генератор включает структуру тегов и PDF-outline для доступности.

## Полная проверка

```bash
npm test
```

Проверка заново генерирует данные из канонического Markdown, собирает production-артефакт `public/` и запускает регрессионный аудит структуры курса, опасных формулировок и публичного allowlist. Дополнительно `tools/verify_site.py` сверяет каждую содержательную строку и ячейку модулей с JSON и опубликованным HTML, проверяет общее вступление, канонические адреса, локальные ресурсы и ссылки на разделы. PDF пересобираются отдельно после изменения текста.

## Аналитика курса

`analytics.js` отправляет в GA4 отдельные события воронки курса:

- `course_cta_click` — переход в курс из hero, программы или финального экрана;
- `course_start` — первый запуск курса в текущем браузере;
- `course_resume` / `course_revisit` — возврат к незавершённому / завершённому курсу;
- `course_module_view` — открытие модуля;
- `course_progress` — достижение 25%, 50%, 75% и 100%;
- `course_complete` — явное завершение курса;
- `course_reset` — сброс сохранённого прогресса.

Прогресс хранится локально в `lr_servitor_progress_v1`. Процент считается по числу открытых модулей; 100% фиксируется только после подтверждения завершения в модуле 10.

## Донаты

Ссылка «Задонатить» задаётся одной константой `DONATE_URL` в `site/_atoms.jsx`: веб-ссылка на донаты из настроек Tribute, которая открывается в браузере (сумма на выбор донатера, российские и зарубежные карты). Пока строка пустая, ссылки на сайте нет. Заполненная ссылка появляется в шапке (на мобильном в меню) и в подвале в колонке «связь» на всех страницах. После изменения: `npm test`.

Клик отправляет в GA4 событие `donate_click` с `link_url`, `page_path` и `creative_slot` (`header` или `footer`). Это переход к оплате, а не донат: факт оплаты виден только в Tribute.

## Раздел ПРИНТЫ

Адреса: `/prints/` (рисунки без фотографий вещей) и `/prints/<slug>/` (рисунок, видео, история, весь ассортимент). Заказ оформляется на FUN.ru, все ссылки туда открываются в новой вкладке с `rel="noopener noreferrer"`.

Данные:

- `content/prints/index.json`: витрина раздела, порядок опубликованных принтов (`prints`), типы вещей для фильтра (`item_types`: тип определяется по названию товара, тип с пустым `match` забирает остальное), шаги "Как заказать", декоративные кружки цветов;
- `content/prints/<slug>.json`: страница принта, история, подписи видео, товары, цвета и точные URL FUN.ru (slug `fnord_diskordianstvo_i_glitch1` в ссылках правильный);
- `content/prints/<slug>.media.json`: карта веб-копий, создается инструментом ниже, вручную не правится.

`npm run build` проверяет связи принт/товар/цвет/URL и наличие файлов (`tools/prints-data.mjs`), встраивает данные в `dist/app.js`, собирает HTML с canonical, Open Graph и sitemap. Компоненты: `site/_prints.jsx`, стили: `brand/prints.css`.

### Изображения

Мастер-файлы (PNG из пакета материалов) в репозиторий не входят. Веб-копии с хешем в имени лежат в `media/prints/<slug>/` и публикуются как `/media/...` с вечным кэшем:

```bash
python tools/prints_media.py images --source <распакованный пакет материалов>
```

Инструмент сверяет sha256 каждого мастера с JSON, делает WebP 480/800/исходная ширина для товаров, lossless WebP рисунка, WebP постера и карточку Open Graph 1200x630, печатает размер и PSNR каждой копии. Оригинал рисунка публикуется побайтово (`artwork-<hash>.png`), `verify_site.py` это проверяет.

Он же делает `thumb-<hash>.webp`: рисунок без прозрачных полей, вписанный в 480x288, для анонса раздела на главной. Отдельно превью пересобирается без пакета материалов, из опубликованного оригинала:

```bash
python tools/prints_media.py thumbs
```

### Видео

Пока `video.src` равен `null`, страница показывает постер без плеера. Подключение готового ролика:

```bash
python tools/prints_media.py video --slug sdelay-tak-chtoby-pylalo --input <путь к ролику>.mp4
npm test
```

Команда проверяет 16:9 (другую пропорцию не обрезает, а отклоняет), удаляет звуковую дорожку, перекодирует в H.264 с `faststart`, пишет `loop-<hash>.mp4` и заполняет `video.src`, `width`, `height`, `duration_seconds`. Плеер: `muted`, `loop`, `playsinline`, автозапуск через `play()`, пауза вне экрана, кнопка паузы под кадром, постер с ручным запуском при запрете автозапуска или `prefers-reduced-motion`. Стык петли проверяется глазами на готовом файле. Если первый кадр ролика заметно отличается от текущего постера, добавьте `--poster-from-video`: постер пересоберется из первого кадра.

### Следующий принт

1. Добавить `<slug>.json` по образцу существующего (стабильные `id`, порядок `order`, мастер-файлы с sha256).
2. Добавить slug в `prints` в `content/prints/index.json`.
3. Запустить `prints_media.py images`, затем `npm test`.

Неподготовленные принты в `prints` не добавляются: пустых карточек на витрине нет.

### Аналитика раздела

- `page_view` с `content_group` `prints` или `print`;
- `print_select`: переход с витрины на принт;
- `print_assortment_view`: ассортимент попал в экран;
- `print_product_click`: клик на FUN.ru, `link_kind` = `card`, `card_color`, `viewer`, `viewer_color`, плюс `item_id`, `item_color`, `link_url`;
- `print_video_play`: ручной запуск видео;
- `prints_teaser_click`: переход в раздел из анонса на главной, `link_kind` = `home_hero`, `print_id` показанного в этот момент принта.

Анонс на главной (`PrintsTeaser` в `site/_prints.jsx`) стоит справа от логотипа и по очереди показывает рисунки. Смена останавливается при наведении, фокусе и вне экрана, после трех кругов возвращается к первому принту и не запускается при `prefers-reduced-motion`.

Обработчики только отправляют событие и не отменяют переход по ссылке; клики не передаются как покупки.
